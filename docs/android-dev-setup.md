# Android Dev Setup

How to build and test Gloss on an Android tablet over USB.

## Prerequisites

### 1. Android SDK & NDK

Install Android Studio, then via **SDK Manager** install:
- **SDK Platform**: Android 14 (API 36) or the latest available
- **SDK Tools**: Android SDK Build-Tools, NDK (Side by side), Android SDK Command-line Tools

Set the environment variables (add to your shell profile):

```bash
export ANDROID_HOME="$HOME/AppData/Local/Android/Sdk"   # Windows default
export NDK_HOME="$ANDROID_HOME/ndk/<version>"            # e.g. 27.0.12077973
```

### 2. Rust Android targets

```bash
rustup target add aarch64-linux-android
```

(Optional, for emulator: `rustup target add x86_64-linux-android`)

### 3. Tauri Android setup

Run the Tauri init check:

```bash
npx tauri android init
```

If the project already has `src-tauri/gen/android/`, this is a no-op. If it reports missing config, follow the prompts.

### 4. USB debugging on your tablet

1. On the tablet, go to **Settings > About tablet** and tap **Build number** 7 times to enable Developer options.
2. Go to **Settings > Developer options** and enable **USB debugging**.
3. Connect the tablet via USB. Accept the "Allow USB debugging?" prompt on the tablet.
4. Verify the connection:

```bash
adb devices
```

You should see your device listed (e.g. `R5CT20XXXXX  device`).

## Bundle libpdfium.so

Gloss uses `pdfium-render` v0.9 which expects **pdfium build 7543 or later**. You need a pre-built `libpdfium.so` for arm64-v8a (the ABI used by modern Android tablets).

### Download

Go to [nicokratky/pdfium-android releases](https://github.com/nicokratky/pdfium-android/releases) and download a release with build number >= 7543 for `android-arm64`.

Alternatively, search for `bblanchon/pdfium-android` or `nicokratky/nicokratky-pdfium-android` on GitHub for pre-built binaries.

The download will contain a `lib/` folder with `libpdfium.so` (and possibly headers you don't need).

### Place the binary

Copy the arm64-v8a `.so` to:

```
src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a/libpdfium.so
```

This directory already contains `libgloss_lib.so` (the app's own Rust library, generated by the build). The Android Gradle Plugin automatically packages all `.so` files from `jniLibs/<abi>/` into the APK.

### Verify

```bash
ls src-tauri/gen/android/app/src/main/jniLibs/arm64-v8a/
# Should show: libgloss_lib.so  libpdfium.so
```

## Run on the tablet

With the tablet connected via USB and `libpdfium.so` in place:

```bash
npm run tauri android dev
```

This will:
1. Start the Vite dev server
2. Cross-compile Rust for `aarch64-linux-android`
3. Build the Android APK via Gradle
4. Install and launch on the connected device

First build takes a while (Rust cross-compilation + Gradle). Subsequent builds are incremental.

## Troubleshooting

### "failed to bind pdfium system library"

The app crashes on startup with this message. Causes:
- `libpdfium.so` is missing from `jniLibs/arm64-v8a/`
- The pdfium build version is too old (missing symbols expected by `pdfium-render` 0.9). Download a newer build (>= 7543).
- Wrong ABI: you placed an x86_64 `.so` but the tablet is arm64. Check the download matches `android-arm64`.

### ADB doesn't detect the device

- Try a different USB cable (some are charge-only).
- Toggle USB debugging off and on.
- Run `adb kill-server && adb start-server`.
- On Windows, you may need to install the OEM USB driver for your tablet manufacturer.

### Gradle build fails with NDK errors

- Verify `NDK_HOME` points to a valid NDK installation.
- Run `sdkmanager --list` and check that `ndk;<version>` is installed.
- The Tauri Android Gradle plugin expects specific NDK versions — check the Tauri v2 docs for the recommended NDK version.

### "linker not found" for aarch64-linux-android

The Rust toolchain can't find the Android linker. Create or update `.cargo/config.toml`:

```toml
[target.aarch64-linux-android]
linker = "<NDK_HOME>/toolchains/llvm/prebuilt/windows-x86_64/bin/aarch64-linux-android24-clang"
```

Replace `<NDK_HOME>` with your actual NDK path and adjust `android24` to your min SDK level.

### Hot-reload / dev URL not connecting

On some networks, the tablet can't reach the dev server on your PC. Try:
- `npm run tauri android dev -- --host` to bind to `0.0.0.0`
- Check that your PC firewall allows port 1420
